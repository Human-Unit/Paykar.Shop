# Animated header search placeholder

Date: 2026-10-06. Workspace: `D:\Workshop\Paykar\Test_Task_Paykar_Shop`. Local `main`, preserving earlier uncommitted catalog/header work.

**ANIMATED SEARCH PLACEHOLDER — ACCEPTED**

## Change

The primary header search has a decorative typing overlay when the field is empty and the search form has no focus. It reuses existing RU/TJ/EN dictionary entries for milk, bread, tea and cookies. These product families were checked against the live API: their Russian-name searches returned 1, 2, 2 and 1 products respectively.

The animation waits 900ms before starting, types at 90ms per character, holds the complete phrase for 1500ms, deletes at 55ms per character, and pauses 400ms before the next phrase. It repeats without a blinking cursor or additional motion effects. Existing muted color, Noto Sans, 16px size, 450 weight, input padding and text baseline are retained.

`SearchPlaceholder` owns the character state and timer; its ticks do not update the search component's query state or unrelated header state. Only one chained timeout is active, and effect cleanup clears it. Language changes remount the typing sequence. Form focus, any input value or active suggestions unmount the animation. Clearing the field keeps focus and normal search behavior; an empty blur restarts after the delay.

The overlay is absolutely positioned within the input's available width, has `pointer-events: none` and `aria-hidden="true"`, and never assigns an input value. The real field keeps its stable accessible label and native placeholder. Reduced motion leaves the native placeholder static, both at initial load and when the setting changes; CSS also restores it immediately while the media subscription updates. The native placeholder is retained during the initial/restart delay.

Only header search animates. The catalog's secondary search remains static. No animation library, dependency, translation duplication, backend changes or search-query normalization was added. Existing name/SKU search semantics remain: backend name matching uses stored Russian product names; localized animation terms describe those real product families, and the focused TJ/EN static placeholder still explains Russian-name/SKU input.

## Actual browser acceptance

Connected Playwright Chrome tested the rebuilt production application at `http://localhost:3000`.

- Observed all four complete Russian phrases, typing, 1500ms holds, deletion, pauses and a full repeat. Mutation samples captured empty input values and closed suggestions throughout. No input events, history changes or search API requests were generated by the animation.
- Focus removed the overlay immediately. It stayed absent while focused and empty, during real typing, and after a nonempty blur. Clear returned focus to the empty input without restarting animation; an empty blur resumed it.
- Real user input still fetched milk suggestions. SKU suggestion selection through ArrowDown/Enter navigated to the yogurt product; normal text submission navigated to the catalog with the typed query.
- Language changes reset to the initial delay, followed by the correct first and second phrases: TJ `Шир`/`Нон`, EN `Milk`/`Bread`. The input remained empty.
- Reduced motion at initial load and through a live media change produced a static native placeholder, with no decorative layer remaining.
- Verified only one animated layer on `/catalog`, in the header; no layer in the secondary search.
- Passed **36 responsive combinations**: RU/TJ/EN × dark/light × **320, 390, 768, 1024, 1440, 1920px**. Input/overlay bounds, text padding/baseline, font size/weight, header/search separation and absence of horizontal overflow were checked. Empty between-phrase text has no glyph baseline and is excluded from that measurement.
- Passing acceptance batches produced zero console errors or JavaScript exceptions. The responsive matrix also generated zero search-query requests.

Evidence: [browser results](animated-search/browser-acceptance.json), including actual mutation timestamps, and [12 screenshots](animated-search/screenshots/) at 390px/1440px across both themes and all languages. Representative RU dark mobile and EN light desktop captures were visually inspected. Preferences were restored to RU/light, and unrelated browser tabs were preserved.

Harness corrections involved explicit locale initialization, polling short text states, waiting for media subscription updates, and targeting the catalog text input uniquely. An optional hidden-tab check could not observe `visibilityState="hidden"` in this attached browser environment. Hidden-tab pausing is implemented through a visibility subscription and timeout cleanup but is not claimed as browser-verified; the temporary test tab was closed. This does not block the requested animation, interaction or reduced-motion acceptance.
